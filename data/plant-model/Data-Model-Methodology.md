# Plant → Entity → Group data model: method and calculations

All data is synthetic mock data, generated by `build_plant_model.py` with a fixed seed (so it is reproducible). The KPI IDs come from `Plant-KPIs.csv`, which was taken from `P1-R1-KPICatalogue.html`. The catalogue's definitions are still placeholders, so the formulas below are working assumptions until they are approved.

## 1. Hierarchy and grain

```
Group
├── Entity A1 ── Plant 01, Plant 02, Plant 03
└── Entity A2 ── Plant 04, Plant 05, Plant 06
```

| Level | Grain (one row per…) | Rows | Source of numbers |
|---|---|---|---|
| Plant (atomic) | plant × month | 6 × 6 = 36 | Mock inputs (the only place data is entered) |
| Entity | entity × month | 2 × 6 = 12 | Roll-up of its plants |
| Group | month | 6 | Roll-up of the entities |

- **Periods:** monthly, 2026-04 to 2026-09.
- **Plant 02** is deliberately set up as the weak plant, and the prototype's narrative is written around it. It has more failures, longer repairs, lower throughput, higher cost, weaker PM compliance and more dispatch delays.

## 2. The core rule: roll up base measures, then recompute KPIs

The model stores two kinds of field:

- **Base measures:** raw additive quantities such as hours, tonnes, counts, money, m³ and GJ. These are the only things that roll up.
- **KPIs:** every KPI, at every level, is recalculated from that level's rolled-up base measures. A KPI is never averaged across child rows.

```
Plant base ──SUM / MIN──▶ Entity base ──SUM / MIN──▶ Group base
     │                         │                          │
  KPI formula              KPI formula               KPI formula   (identical formula at every level)
```

This is what makes the numbers defensible. A ratio KPI averaged across plants is wrong because it ignores plant size. For example, Production vs plan (OPS-001) in Sep 2026:

| | Good output t | Plan t | OPS-001 |
|---|---|---|---|
| Plant 01 | 81,854 | 85,234 | 96.03 % |
| Plant 02 | 95,233 | 121,475 | 78.40 % |
| Plant 03 | 139,711 | 140,379 | 99.52 % |
| **Entity A1** (Σ) | **316,798** | **347,088** | **91.27 %** (not the simple average of 91.32 %) |
| Entity A2 (Σ) | 308,869 | 307,966 | 100.29 % |
| **Group** (Σ) | **625,667** | **655,054** | **95.51 %** (not the simple average of 95.78 %) |

**Roll-up rules:**

- **SUM:** every base measure except one.
- **MIN:** `permit_days_to_expiry`. The parent's permit clock is its nearest expiry. In Sep 2026 Group shows 65, which comes from Plant 02.

## 3. Base measures (plant inputs)

| Field | Unit | Roll-up | Meaning |
|---|---|---|---|
| calendar_hours | h | SUM | 24 × days in month |
| planned_op_hours | h | SUM | Calendar hours minus planned shutdown |
| run_hours | h | SUM | Hours running (= planned_op − unplanned downtime − minor stops) |
| unplanned_downtime_hours | h | SUM | Unplanned stoppages (≥ repair hours) |
| ideal_output_t | t | SUM | planned_op_hours × nameplate rate |
| installed_capacity_t | t | SUM | calendar_hours × nameplate rate |
| planned_production_t | t | SUM | Monthly production plan |
| gross_output_t | t | SUM | All output, including off-spec |
| good_output_t | t | SUM | On-spec output (= reported production) |
| feed_input_t | t | SUM | Raw material fed |
| feed_contained_t | t | SUM | Valuable content in feed (grade × feed) |
| recovered_contained_t | t | SUM | Valuable content recovered |
| prod_loss_downtime_t | t | SUM | unplanned_downtime_hours × nameplate rate |
| failures | count | SUM | Breakdown events |
| repair_hours | h | SUM | Repair time on breakdowns |
| pm_scheduled / pm_completed | count | SUM | Preventive maintenance due / done on time |
| variable_cost_k, fuel_cost_k, fixed_cost_k | currency k | SUM | Fuel is a subset of variable cost; currency is a placeholder |
| water_m3, emissions_tco2e, energy_gj | m³, tCO2e, GJ | SUM | Sustainability inputs |
| production_at_risk_t | t | SUM | Forecast shortfall vs plan |
| critical_plant_alerts | count | SUM | Open critical plant-state alerts |
| critical_material_risks | count | SUM | Critical materials with < 7 days cover |
| dispatches_total / dispatches_delayed | count | SUM | Dispatch performance |
| hours_worked, recordable_injuries | h, count | SUM | TRIR inputs |
| severity_incidents, near_misses, critical_safety_incidents, env_excursions, env_violations | count | SUM | EHS events |
| ehs_ca_open / ehs_ca_overdue | count | SUM | Corrective actions (overdue ≤ open) |
| investigations_due / investigations_completed | count | SUM | EHS investigations |
| permit_days_to_expiry | days | **MIN** | Nearest licence or permit expiry |

`nameplate_tph` is a plant attribute, used only to generate the data. It is not rolled up.

## 4. KPI formulas (the same formula at Plant, Entity and Group)

| KPI | Measure | Unit | Formula |
|---|---|---|---|
| OPS-001 | Production vs plan | % | good_output_t ÷ planned_production_t × 100 |
| OPS-003 | Capacity utilization | % | good_output_t ÷ installed_capacity_t × 100 |
| PLT-001 | Asset utilization | % | run_hours ÷ calendar_hours × 100 |
| PLT-002 | OEE | % | good_output_t ÷ ideal_output_t × 100 (= Availability × Performance × Quality) |
| PLT-004 | Recovery percentage | % | recovered_contained_t ÷ feed_contained_t × 100 |
| PLT-005 | Yield | % | good_output_t ÷ feed_input_t × 100 |
| REL-001 | MTBF | h | run_hours ÷ failures |
| REL-002 | MTTR | h | repair_hours ÷ failures |
| REL-003 | Unplanned downtime | h | unplanned_downtime_hours |
| REL-004 | Production loss from downtime | t | prod_loss_downtime_t |
| REL-005 | PM compliance | % | pm_completed ÷ pm_scheduled × 100 |
| CST-001 | Cost per tonne | currency/t | (variable_cost_k + fixed_cost_k) × 1000 ÷ good_output_t |
| CST-002 | Variable cost | currency k | variable_cost_k |
| CST-003 | Fuel cost | currency k | fuel_cost_k |
| SUS-001 | Water usage | m³ | water_m3 |
| SUS-002 | Emissions | tCO2e | emissions_tco2e |
| SUS-003 | Energy intensity | GJ/t | energy_gj ÷ good_output_t |
| SIG-007 | Production at risk | t | production_at_risk_t |
| SIG-008 | Critical plant-state alerts | count | critical_plant_alerts |
| SIG-009 | Critical-material shortage risk | count | critical_material_risks |
| SIG-012 | Dispatch delays | % | dispatches_delayed ÷ dispatches_total × 100 |
| SIG-021 | Environmental violations | count | env_violations |
| EHS-001 | TRIR | per 200k h | recordable_injuries × 200,000 ÷ hours_worked |
| EHS-002 | Severity incidents | count | severity_incidents |
| EHS-003 | Near misses | count | near_misses |
| EHS-004 | Critical safety incidents | count | critical_safety_incidents |
| EHS-005 | Environmental excursions | count | env_excursions |
| EHS-006 | Open EHS corrective actions | count | ehs_ca_open |
| EHS-007 | Overdue EHS actions | count | ehs_ca_overdue |
| EHS-009 | EHS investigation completion | % | investigations_completed ÷ investigations_due × 100 (100 if none due) |
| REG-006 | Permit expiry clock | days | permit_days_to_expiry (MIN of children) |

**Excluded on purpose:**

- **SIG-001, SIG-002, SIG-003:** these are aliases of REL-003, PLT-005 and PLT-004, so they take those values. They are not stored separately.
- **OPS-001 and OPS-003:** both are defined once, in T1, and are computed here from plant data.
- **Ratios with a zero denominator:** these return 0. The exception is EHS-009, which returns 100 when no investigations are due.

**Caveat:** summing tonnes across plants assumes that all plants make a comparable product. If real plants make different products, the Group-level tonnage KPIs (OPS-003, CST-001, SUS-003) need a common unit or an equivalence factor.

## 5. From model value to what the prototype shows

`export_to_prototype.py` turns each KPI into a card for every scope: Plant01–Plant06, A1, A2 and Group. Card values are for P06 (Sep 2026), and the sparkline covers P01–P06.

Targets are working assumptions. They are set only where one target makes sense at plant, entity and Group alike: ratios, or counts with zero tolerance. Additive totals (hours, tonnes, ₹, m³) have no target, because the right target depends on the size of the scope.

### 5.2 Card fields

| Field | Rule |
|---|---|
| `v` | P06 value ÷ display divisor, rounded to the display precision |
| `var` | value − target, shown in pts for % KPIs and in the KPI's unit otherwise |
| `tr` | P06 − P05, with ▲/▼ showing the direction of change (not good or bad) |
| `bs` (with a target) | Meets target → On track. Misses target and moved the wrong way since P05 → Deteriorating. Otherwise → Intervention required |
| `bs` (no target) | Moved the wrong way → Deteriorating. Moved the right way → Improving. Flat → On track |
| `sp` / `spp` | P01–P06 actual and target, indexed to P01 = 100 |
| `ts` / `prov` | Certified / CERT P06 (every model value is a certified month) |
| `fb` (footer) | Only where a model fact belongs on the card (OPS-001 Group/A1/Plant 02) |

Point-in-time variants (e.g. `Group#t7`) take the same model value and keep only their own trust state.

### 5.3 Aliases (same value, different ID)

| Alias | Canonical KPI |
|---|---|
| SIG-001 | REL-003 |
| SIG-002 | PLT-005 |
| SIG-003 | PLT-004 |
| OPS-005 (capacity utilisation) | OPS-003 |
| OPS-006 (OEE · Group weighted) | PLT-002 |

### 5.4 "Without it" (child effect)

For every parent and child, the parent is recalculated from the other children's summed (or MIN) inputs. The effect of the child is parent − parent-without-child.

Example, OPS-001 P06: Entity A1 = 91.27% and A1 without Plant 02 = 98.21%, so Plant 02 moves Entity A1 by −6.9 pts. Group without Plant 02 has an OEE of 87.1% against 84.1% actual.

### 5.5 Key facts the narrative is built on (P06)

| Fact | Value |
|---|---|
| Group production | 625,667 t ÷ 655,054 t = 95.5% of plan; gap 29.4 kt |
| Plant 02 production | 95,233 t ÷ 121,475 t = 78.4% of plan; gap 26.2 kt (89% of the Group gap) |
| Plant 02 reliability | OEE 70.3% · MTTR 11.4 h (5.7 h in P01) · 6 failures · 78.2 h unplanned downtime · 14.8 kt lost · PM compliance 81.8% · ₹3,245/t · 16% of dispatches late · 24.3 kt at risk |
| Entities | Entity A1 91.3% of plan; Entity A2 100.3% |
| Permit clock | Lowest in the Group is Plant 02, at 65 days |

## 6. How the prototype uses the model

- **`js/data/base-data.js`:** `kpi[ID][scope]` holds the cards above. `DCTData.plant` holds the monthly series, formulas, P06 inputs per scope, the children map and the "without it" values.
- **`js/data/resolve.js`:**
  - Fills cards, tables (KPI ID in column 1 or 2) and tiles.
  - Fills model-bound blocks: tables with `kcols` (column → KPI) and bar charts with `kpi`. The scope comes from each row's label.
  - Adds a **roll-up tab** to every Entity, Core Group and Owner page that shows plant KPIs. Entity pages get Plant 01–03 → Entity A1; Group and Owner pages get Plants → Entities → Group.
  - Links every plant-KPI value to its lens's KPI detail page: S-03e (Entity), S-03 (Core Group) or S-03o (Owner), as `?kpi=ID&scope=…`.
- **KPI detail page** (`DCTResolve.kpiDetail`): shows the roll-up chain, plants by bar, the full calculation table (plant inputs → entity Σ → Group Σ), each child's contribution, monthly values, definition, lineage and trust.
- **Hardcoded values:** anything not derivable is listed in `data/HARDCODED-VALUES.md`.
- **Rebuild everything:**
  ```
  python3 data/plant-model/build_plant_model.py
  python3 data/plant-model/export_to_prototype.py
  node tools/regen.js
  ```

## 8. Integrity checks

**Built into the generator** (the script stops if any check fails):

- **Reconciliation:** for every base measure and month, Σ plants = Σ entities = Group (or MIN for the permit clock).

**Built into the mock data by construction:**

- run_hours ≤ planned_op_hours ≤ calendar_hours
- unplanned_downtime_hours ≥ repair_hours
- good_output ≤ gross_output ≤ ideal_output
- recovered_contained ≤ feed_contained
- fuel cost ≤ variable cost
- overdue ≤ open corrective actions
- investigations completed ≤ due
- PM completed ≤ scheduled
- dispatches delayed ≤ total
